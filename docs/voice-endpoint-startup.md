# 启动保存远程地址与手机手动更新

2026-11-02，App 1.3.1。

沿用 Cloudflare Quick Tunnel，没有新增公网服务器或固定发现服务。每次 voice-tunnel 容器启动，entrypoint 清空本次启动日志，启动一次性地址保存进程，然后由原 cloudflared 接管主进程。保存进程仅在启动阶段读取日志并验证远程设备认证入口可达，最长等待 120 秒，保存一次后退出。容器启用 init 回收退出子进程；没有常驻更新线程、定时任务、Windows 进程、Docker socket 或 ADB 调用。启动检查有短暂资源开销，不能宣称完全零资源。

保存文件：`media/voice-connection/current.json`，仅有 HTTPS 地址和 UTC 保存时间。使用临时文件加原子替换，失败保留旧文件。web 容器以只读方式挂载此目录。登录后的设备管理页可显示、刷新、复制，设备凭据不能调用这个网页账号接口。显示刷新不会重新启动地址保存任务。

手机：设备连接 → 更新连接地址 → 粘贴 → 验证并更新。已有加密配对凭据用于验证候选地址，10 秒连接和 10 秒读取预算，禁止 HTTP 与重定向；验证失败保留原地址。当前没有固定地址查询入口，跨网络自动获取新地址没有实现，也没有宣称已经实现。

实机观察：容器成功写入地址并输出完成日志后，进程列表只剩 docker-init 和 cloudflared，没有 Python 更新进程；一次空闲采样通道 CPU 为 0.00%，总内存约 21 MiB（包括原有通道）。相关 PostgreSQL 检查 20 项通过。
