## 数字核对与适用范围

统一使用十进制 TB。示例假设平均文件 5 MB、可解析率与向量化率均为 1、未知去重率为 0，得到 1 亿份文件。每份 20 / 50 / 200 段分别对应 20 亿 / 50 亿 / 200 亿向量点。

2048 维 fp32 原向量每点 8192 B，int8 附加表示每点 2048 B；图开销 128 B/点是待验证假设。单副本单代向量合计 **20.736 / 51.84 / 207.36 TB**；两副本两代 **82.944 / 207.36 / 829.44 TB**。中档两副本两代再留 30% 空闲为 **296.23 TB**，仍未计 payload、稀疏/全文索引、日志、快照、构建临时、备份、原件层或 PG。

按 2.3 KB/解析段的示例，PG 分段表为 **4.6 / 11.5 / 46 TB**，未计真实行开销、索引膨胀和副本。平均文件大小与分段密度必须联合分层抽样，不能由 500 TB 直接认定 50 亿点。

500 TB 原件按理想 EC 4+2 系数 1.5 得 750 TB；单站点预留 30% 空闲约 **1.0714 PB 原始盘**，不含版本、对象元数据、暂存或备份。原有源盘是否保留与是否另建原件副本单独核算，避免把所有存储池混成一个总盘数。

主情景 50 亿点在 30 / 90 / 180 / 365 天的日历平均嵌入需求分别约 **1929 / 643 / 321.5 / 158.5 段每秒**；完整读取原件一遍分别约 **192.90 / 64.30 / 32.15 / 15.86 MB/s**。这些只是平均理论下限；实例选型必须扣除末尾构建、验证、追平窗口，再考虑可用时长、重试、新增负载与共享资源预留。GPU 型号和数量由具体模型基准决定。

## 本轮复审修正

- 保留 2048 固定维度及全部可处理资料的最终覆盖目标，冷热仅改变回填顺序和驻留层。
- 删除输出维度翻倍推整卡显存翻倍的推断；OCR 与嵌入按实际 CPU/GPU 资源池隔离，不假定互不影响。
- 暂存改为原件与解析临时两套原子字节预算；取消后先阻止旧写入者，实际清理后才释放占盘预算。对象端强制配额、URL 重放、版本与分片残留纳入实现和集成验收条件。
- 容量按物理集合、实际副本和阶段逐项求和，正常/换代/恢复分开；旧 1024 存量按实际规模，不假设已有 500 TB 向量化。
- 节点容量含查询扇出、热点、资源池边界及丢一台主机后的剩余能力。增加分片不能直接视为查询吞吐线性增长。
- 把安全安装及已验证备份恢复设为正式批量写入前的 G0 门槛；过滤 schema 和 payload index 设计创建前置。后期是目标规模复验。
- 区分已写入、构建中、达到可检索标准三种状态；离线新集合可评估延后 HNSW，在线生产写入不一律关闭索引。
- 核对现有集合命名实际为库加 generation；模型/维度后缀辅助方法没有调用者。新增 2048 代次与不可变 manifest 的绑定仍属规划。
- 现场历史事实和本轮源码检查分开，未冻结的作者实时读数不作为独立证据；新版 Qdrant 文档不能替代 1.15.5 参数验证。

原有 14 项审查意见继续逐项保留实施待验证状态，未把设计修订计为产品实现通过。
