## 已复现缺陷

### 1. 整库重建超过 50 份无法按界面提示续做

位置：`apps/planner/services.py` 的 `_reset_library_index`，默认 `RESET_LIBRARY_LIMIT = 50`；界面提示位于 `apps/webui/static/webui/kb-pages.js` 的 `resetLibraryIndex`。

独立构造 51 份合成原件，正常执行两轮提案、三次确认、执行。仅将模型重建调用替换成恒定成功，以排除网络与模型失败；批次选择、确认与结果生成使用当前产品实现。

结果：两轮均处理同样的前 50 份，均返回 `remaining=1`、`complete=false`，第 51 份从未进入处理。没有续做游标或已完成批次记录。界面“可再执行一次续做”的提示不成立；超过 50 份时旧代次清理也无法达到全部完成条件。

证据：`artifacts/acceptance/independent-rebuild-continuation-20261016.json`。这是当前代码的非模型缺陷，不依赖 AS711 是否在线。

### 2. 重排响应格式异常时，搜索降级标记遗漏

位置：`apps/knowledge/pipeline.py` 的重排异常处理；`apps/webui/static/webui/kb-search.js` 依赖 `report.degraded` 显示降级提示。

独立诊断保留真实 `RerankClient` 和生产搜索异常处理，将 HTTP 响应替换成状态 200、缺少 `results` 的合成错误响应；向量召回与嵌入被替换为正常合成结果，未向 AS711 或生产库发送请求。

结果：返回 3 条回退结果，`rerank.applied=false` 且 `rerank.error` 有明确错误，但 `degraded=false`、`degraded_reason` 为空。因此搜索页不会按现有逻辑显示降级提示。普通响应结构异常与带“不可用”字样的错误走了不同告警口径。

证据：`artifacts/acceptance/independent-rerank-degradation-20261016.json`。

诊断脚本第一次运行的钩子参数、第二次运行的合成召回函数签名有误；修正诊断工具后复现上述结果。工具自身错误未计为产品缺陷；完整回归仍为上表结果。

## 尚未提供的操作与能力边界

- 系统配置中的“全部切换为远程”“启动模型”“切换为本地推理”“切换为远程接口”仍为 `disabled`。浏览器与代码均确认。用户已明确“本地”指 AS711 模型，且不得启停其他服务；当前页面却以固定远程接口为由禁用这些操作。连接推理端点本身不会补出受控模型管理能力。
- 文件页“重置数据库”现在可以点击，但只显示“这个按钮不会执行任何清库操作”的说明。替代入口是信息库的重置索引与受控删除；应如实作为能力边界说明，不能把说明弹窗等同数据库重置实现。
- “学习”目前是实时、有界的检索反馈加权与只读规则报告；不是模型训练或自动更新模型参数。是否满足用户对“学习”的期望，应按这一实际含义判断。
- 熔断器状态和 `reset_breaker` 仅作用于当前 Python 进程的 `BREAKERS`，不是 web/worker 全局重置。当前指标声明 `scope=process`；不能把此操作理解为清除了所有 worker 的熔断状态。
- OCR 与重排的页面“测试连通”使用 `GET /models`，不执行真实推理，且这条探测没有携带模型客户端的鉴权头。接口只支持推理路由或要求鉴权时，可能误报不连通；本次 AS711 离线，未验证这种条件在实际服务器上是否存在。
- Agent 页仍显示旧的缺失向量集合登记，以及归属为“—”的历史记录。维护命令已存在，但本次没有替用户删除历史登记；这些记录不能作为当前可用索引证明。

页面证据：`artifacts/acceptance/independent-audit-model-controls-20261016.png`、`artifacts/acceptance/independent-audit-reset-explanation-20261016.png`。
