## 本机启动

1. 从项目根运行 `python scripts/fetch_voice_tools.py`，获取并校验固定版本的隧道组件。
   同时运行 `python scripts/fetch_voice_model.py` 下载并校验固定版本的本地中文转写模型，避免启动时依赖在线模型下载。
2. 按原项目方式运行 `pwsh -File deploy/build-app.ps1` 构建当前应用。
3. `docker compose -f docker-compose.yml -f deploy/docker-compose.voice.yml build`。
4. `docker compose -f docker-compose.yml -f deploy/docker-compose.voice.yml up -d`。
5. 从 voice-tunnel 日志读取实际 HTTPS 地址；在“设备管理”中添加设备，或使用本机配置脚本为指定用户添加 Note 4。

新增服务包括 voice-worker（持久任务消费进程）、voice-asr（本地中文转写）、voice-gateway（仅开放设备路径）、voice-tunnel（从本机发起的 HTTPS 隧道）。原网页仍在本机 8800 端口；外部入口只转发设备接口。

语音 worker 直接消费 PostgreSQL 中的持久 queued 记录，避免任务创建与队列投递之间的空窗，不与资料解析的 Celery worker 抢占队列。第一版一个语音 worker 串行执行任务；后续可增加 worker 实例，任务 CAS 和会话租约负责排他。

## 设备与网页

- `/app/devices/`：添加多台设备、修改名称和发送设置、启用/停用、重新发放凭据及移除。
- 设备凭据只显示一次，服务端仅存摘要。每台设备独立拥有 device_id、目标会话、知识库范围和设置版本。
- 网页可见时拉取设备事件。空输入框显示新语音；手工草稿和用户后续编辑不被覆盖。网页不重复提交设备消息。
- 转写与回答可由设备下载中文 400×300 黑白页面；单页 15,000 字节，并校验 SHA-256。
- 非删除操作经知识库权限校验后直接执行；资料删除仍在网页走原有确认。手机可对本设备拥有的任务会话发起一次确认删除，不能通过该接口删除资料或知识库。

## 故障与恢复边界

录音、ASR 与页面渲染错误分别处理。已提交模型但结果不明时标记 uncertain，不自动再次请求模型或重复创建提案。已保存的用户消息和回答与任务建立持久关联。进程崩溃时，过期的模型执行租约会阻止同一会话被另一进程接管；管理员必须先确认旧进程已经结束，再检查会话记录并处理残留租约，不能直接超时抢占。

原始音频是临时数据，终态任务超过一小时后由 worker 清除；未上传的板端音频只保留在 PSRAM。第一版固件不做电池深睡眠与 OTA，更新与恢复通过 USB。临时隧道重建会改变地址，需要重新写入设备服务地址。

## 速度与翻页改进（2026-10-27 最终版本）

用户在实测后明确要求撤回流式预览，恢复按住录音、松手后一次性完整转写并发送。固件、设备 API、网页预览同步及 ASR 预览实现均已移除；仍使用手机热点，蓝牙方案后续再做。

本次保留的优化：

- HTTPS 连接复用；每批最多 8 帧、SHA-256 校验；最多 64 页 PSRAM 缓存。按键直接把缓存页送入显示队列；网络慢时不回放已经过时的目标页。缓存之外的页面仍需要联网。
- 服务器对文字排版和帧做有界缓存。网关支持隧道重新分块后的 HTTP 正文，限制总长度、分块头尾长度和分块数量，拒绝 Content-Length 与 Transfer-Encoding 冲突，认证和设备隔离继续生效。此前间歇性 HTTP 400 已确认来自旧网关拒绝 Transfer-Encoding。
- 首帧建立黑白基准，之后调用驱动已有的黑白过渡刷新；每 8 次完整刷新清残影，局刷失败回退完整刷新。未启用实验灰阶。实测驱动局刷约 0.89～0.91 秒，完整刷新约 1.27 秒，不能把排队完成当作物理屏幕已经完成。
- 短按切换内容时不再先刷新就绪页；跳过相同帧；连续按键以最新目标页为准。重启后恢复最近一次已完成回复并缓存页面。
- 新录音直接幂等上传，去掉先查不存在再上传的往返。空正文回复显示真实拒绝原因或无正文提示，避免无限取图。
- TCP 发送窗口从 5,760 提高至 65,535，接收窗口提高至 32,768，接收邮箱 32，允许 Wi-Fi/LwIP 使用 PSRAM。网络传输时关闭板端 modem sleep，空闲时恢复。
- 语音 worker 的共享限流/熔断 Redis 地址曾误指向容器本机，现显式指定容器 Redis DB14，连接检查通过。

实测边界：旧配置 9.64 秒 / 308,524 字节的录音上传耗时 56,478 ms。新配置一次成功的 414,124 字节上传约 10,564 ms，但该轮此前还遇到一次上传超时与约 30 秒 HTTP 530 隧道中断，因此不能把 10.6 秒当作该轮完整端到端耗时。另一轮长回复在模型端点连续两次 60 秒超时，任务已标记 uncertain，未重放。最小 16-token 模型请求 0.64 秒返回只证明当时端点可用，不能代表长回复速度。

流式试验未通过用户实物验收，已按用户要求撤回，历史试验日志仅保留在本机忽略目录中，不作为交付功能。最终版本恢复单次转写后，用户实物确认“正常了，翻页也快了”，完成本轮翻页验收。

## 双击取消发送（2026-10-27 收尾）

用户在实测后要求增加“松手后撤回误触发送”。最终规则：录音松手后快速短按两次正面按钮，两次短按松开间隔不超过 350 ms，取消最近一条发送；录音松手本身不算一次短按。发送前有 800 ms 宽限；短按判定 200 ms、扫描 30 ms 去抖，录音时按上键取消保留。

板端状态机（firmware/note4/main/app_main.cc）：

- 上传尚未开始（send_phase=Waiting）时，`ask_cancel()` 用 `send_phase.compare_exchange_strong` 抢先把 Waiting 换成 LocalCanceled，上传任务因此不会发出请求；只清空 NVS `pending`、显示“已取消发送”，服务端不产生任何记录。
- 已在上传或等待回复（Sending）时置 `cancel_requested`、显示“正在取消”，由 `cancellation()` 任务轮询 `POST turns/<client_id>/cancel/`：返回 200 且 `state=canceled` 显示“已取消发送”；409 显示“来不及取消”并清 `cancel` 键；其它失败每 1500 ms 重试。
- NVS 键 `pending`、`cancel` 记录未完成发送；重启后若 `cancel` 与 `pending` 相同则自动补发取消，避免断网重启后重复提交。
- 取消完成由 `finish_canceled()` 清 `pending`/`cancel`、恢复取消前的 turn、页面与视图后回到空闲，可直接再录。

服务端（apps/voice/services.py `cancel_turn`）：

- 设备行锁 + `select_for_update` 取任务；已 canceled 直接幂等返回；仅 queued/transcribing/transcribed 或 ASR 阶段 failed、且没有用户/回答消息的任务允许取消。
- 任务尚不存在时先落一条 state=canceled、audio_path="" 的记录，保证慢上传随后到达也不会重建活任务；`accept_audio` 对已取消任务返回 existing、不再派发。
- ASR 前后各检查一次取消状态，异常分支同样先读状态，避免迟到的识别或失败覆盖取消结果。
- 太晚（已进入 AI）返回 409 与「已进入 AI 处理，无法取消这条发送」。

页面与网关：新增 400×300 状态页“正在取消 / 已取消发送 / 来不及取消”；网关白名单加入 `/turns/<uuid>/cancel/`；网页语音事件列表包含 `turn.canceled`。

验收证据：

- 单元测试：SQLite 语音套件 35 项（取消 10、设备 15、网关 10），34 通过 1 跳过（跳过的仅真 PG 跨连接并发用例）；容器网络内 PostgreSQL 取消套件 10/10 通过。
- 真实设备：16:34:42 一次真实录音（音频 139,564 字节已上传）双击取消，任务 33ee8fbd 在创建后 10 ms 内转为 canceled，只有一条 turn.canceled 事件，没有用户/回答消息，识别未执行。
- 公网隧道实测（设备凭据）：已取消任务再次取消返回 200 且 task_id 不变；answer_ready 任务取消返回 409「已进入 AI 处理，无法取消这条发送」；无凭据 401。
- 部署：kb-app:delivery 16:28 重建并重启 web/worker/scheduler/voice-worker；voice-gateway 16:27:59 重建；固件 16:26:44 构建（1,338,320 字节），16:30 只刷应用区 0x10000 并由 esptool 校验通过，设备 16:33 重新上线配置成功。

遗留与注意事项：

- “AI 已开始后双击”的板端“来不及取消”界面尚未人工拍照确认；服务端 409 与固件显示逻辑已分别验证。
- 取消并发用例要求真实 PostgreSQL：宿主机直连 127.0.0.1:55432 会得到 “server closed the connection unexpectedly”，须在容器网络内运行。镜像按 .dockerignore 不含 tests/ 与 scripts/，容器内需先复制 `pytest.ini`、`tests/`、`scripts/` 到 /app 再以 `--kb-db=postgres` 运行。
- 取消允许作用于 ASR 阶段 failed 的任务（会把该任务状态改为 canceled）。
