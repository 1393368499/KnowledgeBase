# 公文模板真正生效：结构、落款、成文日期、Word 与预览排印（2026-10-19）

> 部署镜像：`kb-app:delivery` = `sha256:7552143ff126e374d600c9036a14405c570032ef50aa9c25cebb122e6b6faad5`（2026-10-19 15:17:28 构建，web/worker/scheduler 均为该镜像）
> 触发：用户 m02105「生成的这份文档似乎并没有按照公文模板编写」

## 1. 问题：套了公文模板，产出的却不是公文

实测（模板「公文基本规范模板」，2026-10-19 14:46 生成）：

| 期望（模板/公文规范） | 实际产出 |
| --- | --- |
| 标题居中、方正小标宋二号 | Word 里是 `Normal` 正文段（模板里没有 `Title` 样式，退化了） |
| 「一、」黑体三号 / 「（一）」楷体三号 / 「1.」仿宋三号加粗 | 全是 Markdown `##` → Word `Heading 2`（楷体），“层级全偏一级” |
| 正文仿宋三号、首行缩进两字符、行距固定 28 磅 | docx 里正文样式没落实，预览是通用 Markdown 排版 |
| 落款单位、成文日期各占一段、居右 | 两行被 Markdown 合并成一段，居左 |
| 成文日期 = 签发当天 | 写成了 `2026年10月15日`（当天 10-19，资料里也没有这个日期） |
| 不出现模板里的示例值 | `（联系人：陶鑫宇，13xxxxxxx）` 原样抄进正文 |

## 2. 根因（四层，缺一层就“看着像公文、其实不是”）

1. **提示词只有“格式建议”，没有结构契约**：`template_prompt_block()` 把模板正文折成一段约束注入 system，但没告诉模型“公文用「一、」「（一）」分条、不写要点符号和表格”。
2. **模板正文本身是排版说明**（`01.公文基本规范模板.docx` 的 223 字讲的都是字体字号行距），模型无法把它映射成 Markdown 结构。
3. **没有占位符/日期校验**：模型照抄 `13xxxxxxx` 也照样入库；成文日期凭空写也没人拦。
4. **导出与预览的排印映射错**：Word 导出只在模板是 `.docx/.dotx` 时复用样式表，但标题级别按 Markdown 直接映射（`##`→Heading 2）；`flush_paragraph()` 把相邻行用空格拼成一段，落款日期检测与右对齐因此失效；预览只是通用 Markdown HTML。

## 3. 修复（4 层，都在本仓库，AS711 未动）

### 3.1 结构契约（`apps/planner/document_templates.py`）
`template_prompt_block()` 的 `official` 分支追加公文结构契约：标题不加编号；正文用「一、」「（一）」「1.」分条；**不用项目符号、不堆表格**；落款单位与成文日期各占一段；附件逐项列；日期按当天；模板里的 `xxx`/`13xxxxxxx`/`某某` 是示例值，一律不得出现。

### 3.2 生成期护栏（`apps/planner/services.py`）
- 提示词里明确「今天是 YYYY年M月D日」。
- **占位符守卫**：命中模板占位符模式就先让模型改一次，仍泄漏 → `PlannerError`，不保存（宁可让用户重来，也不把示例电话存成正式公文）。
- **成文日期守卫**：落款日期既不是今天、也没在资料片段里出现过 → 让模型改一次；仍不对 → 把那一行改成今天（成文日期是签发日，写今天有据可依；丢整份文档或留假日期都更糟）。

### 3.3 Word 导出（`apps/planner/document_export.py`）
- 标题直接格式：22pt 加粗、方正小标宋简体、居中（不依赖模板是否有 `Title` 样式）。
- 标题级别上提一级（`##`→Heading 1），并识别「一、」「（一）」「1.」三类分条行，套 Heading 1/2/3（短行、不以标点结尾、不是附件文件名才认）。
- 列表项降级为正文段；段落按原始行还原（落款单位、日期各成一段）。
- 落款单位与成文日期居中改为**居右、去首行缩进**；正文写入 `w:eastAsia` 字体（仿宋），固定 28 磅行距。

### 3.4 前端预览（`kb-assistant.js` + `kb-home.css`）
- 文档详情接口补 `template_category`；预览容器按 `official` 切换 `.is-official`。
- 预览前给落款补空行（Markdown 会把相邻行合并），渲染后给分条行/落款打 `gb-h1|gb-h2|gb-h3|gb-signature|gb-title` 类。
- CSS：标题 29.33px 小标宋居中、一级黑体、二级楷体加粗、正文仿宋 21.33px、首行缩进 2em、行距 37.33px（28 磅）、落款居右。

## 5. 回退与边界

- 回退：三处各自独立 —— 去掉 `template_prompt_block` 的 `official` 分支、去掉 `compose_document` 的两段守卫、还原 `document_to_docx` 的 `official` 分支与预览的 `decorateOfficialPreview()`/`.is-official` 样式。
- 边界：
  - 只对模板类别 `official` 生效；其他模板与无模板文档的导出/预览口径不变。
  - 字体依赖本机是否装有小标宋/仿宋/黑体/楷体；缺字体时按 CSS 回退族显示，版式不保证与 Word 完全一致。
  - 已有文档不会自动重排：需要重新生成，或在编辑器里导出时按当前模板重新排版。
  - 正文内容仍由模型生成，事实细节需人工核对（本次仍是“草稿”语义）。
