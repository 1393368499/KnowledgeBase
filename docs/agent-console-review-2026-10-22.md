# Agent 控制台检查与修复（2026-10-22）

范围：六张状态卡、五项统计、五个运维动作、索引代次切换/回退、反馈分诊、事件时间线及审计校验。修复已部署到当前 Docker 实例。

## 已修复

| 问题 | 现在的行为 |
|---|---|
| 手动巡检会掩盖周期调度心跳过期 | 周期心跳只依据 `source=beat`；没有周期记录时显示未知，手动检查不证明 scheduler 正常。状态卡同步显示过期警告。 |
| 读取接口失败被显示为空数据或正常 | 运行指标、资料处理统计、操作记录、索引、反馈、审计均区分失败、403 与真实空集，支持刷新重试。 |
| 熔断卡只看当前 web 进程，遗漏 worker 状态 | 共享存储可用时读取全局 `shared` 快照，降级时读取进程内快照；并发闸门故障不会让资源卡保持绿灯。 |
| 我的操作成功率只统计最新 100 条 | 后端聚合当前用户全部历史记录，成功数与终态数独立于列表窗口；终态包括执行完成、失败、过期、放弃。重启指标明确标为“重启操作次数”，不冒充实际重启的资料份数。 |
| 缺失、无归属或未构建完成的索引也能点击切换 | 禁用无效切换入口；没有可用回退目标时禁用回退。权限和完整性仍由后台复核。旧登记保留。 |
| 运维结果只在短暂 toast 中显示，内容还可能被截断 | 用可关闭结果窗口显示说明、逐资料/服务结果及失败信息；提交期间禁用按钮，取消后恢复，阻止连点重复提交。 |
| 学习规则报告可能被同一资料的大量反馈挤满 | 先按资料 ID 去重，再取报告样本；明确本次展示范围，不将其说成模型训练。 |
| 审计校验遇到第一处错误就停止，无法判断全部异常范围 | 继续流式检查，报告异常总数、首条位置及有界明细；保持失败结论，保留全部原始数据。 |

## 功能验证

- 五个运维动作：立即巡检、重启停滞任务、重置熔断器、查看学习规则、重扫未处理反馈，均通过真实 API 的提案、确认、执行协议检查；未确认执行、重复执行及普通账号越权均被拒绝。
- 停滞任务推进和反馈重扫的候选筛选、失败/租约占用/未完成结果分类通过定向用例。处理依赖在隔离测试中受控，不在业务资料上制造故障或执行重建。
- 熔断状态及跨进程重置在本轮独立 Redis 容器中验证，使用独立前缀，测试实例已停止并自动删除；未清理或污染业务 Redis。
- 浏览器状态测试覆盖失败与无权限提示、共享熔断、周期心跳过期、无效代次按钮、长期可读的结果、内容转义、成功率统计及防重复提交。
- 部署后的真实浏览器：管理员能加载所有卡片，巡检经确认执行并检查现有 50 份资料、保存结果；学习规则说明可读；审计校验如实报告历史异常；普通账号管理员动作置灰且显示权限说明。未发现页面 JavaScript 异常。
- web、worker、scheduler 各核对 162 个源文件与前端文件，均与工作区一致；六个常驻服务均 healthy。
